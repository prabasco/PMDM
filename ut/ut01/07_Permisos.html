    Los permisos en Android¶

    Los permisos en Android forman parte del modelo de seguridad del sistema operativo. Su objetivo es proteger la privacidad del usuario y controlar a qué datos, recursos y funciones del dispositivo puede acceder una aplicación.

    Por defecto, cada aplicación Android se ejecuta dentro de un entorno aislado denominado Application Sandbox. Esto impide que una aplicación pueda acceder libremente a los datos de otras aplicaciones o a determinados recursos protegidos del sistema.

    Cuando una aplicación necesita acceder a información o funcionalidades protegidas, debe utilizar el sistema de permisos de Android.

    Los permisos pueden restringir el acceso a:

    • Datos sensibles:

      • Contactos.
      • Ubicación.
      • Calendario.
      • Fotografías y vídeos.
      • Información relacionada con la salud.

    • Hardware del dispositivo:

      • Cámara.
      • Micrófono.
      • Bluetooth.
      • Dispositivos cercanos.

    • Acciones restringidas:

      • Realizar llamadas.
      • Enviar SMS.
      • Mostrar contenido sobre otras aplicaciones.
      • Modificar determinados ajustes del sistema.

    Principio fundamental

    Una aplicación debe solicitar únicamente los permisos estrictamente necesarios para realizar sus funciones.

    Siempre que sea posible, se deben utilizar APIs que permitan realizar una operación sin solicitar permisos.

    Declaración de permisos¶

    Los permisos que necesita una aplicación se declaran normalmente en el archivo:

    AndroidManifest.xml

    Para ello se utiliza el elemento:

    <uses-permission android:name="NOMBRE_DEL_PERMISO" />

    Por ejemplo, para indicar que una aplicación necesita acceder a Internet:

    <uses-permission android:name="android.permission.INTERNET" />

    Para utilizar la cámara:

    <uses-permission android:name="android.permission.CAMERA" />

    Y para acceder a la ubicación:

    <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />

    Declarar no siempre significa conceder

    Declarar un permiso en AndroidManifest.xml no significa necesariamente que la aplicación ya pueda utilizarlo.

    Algunos permisos se conceden automáticamente, mientras que otros necesitan además la autorización explícita del usuario durante la ejecución.

    Tipos de permisos¶

    Android clasifica los permisos principalmente según el nivel de protección que necesita el recurso al que permiten acceder.

    Podemos distinguir tres grandes situaciones:

    1. Permisos concedidos durante la instalación.
    2. Permisos solicitados durante la ejecución.
    3. Permisos especiales.

    1. Permisos concedidos durante la instalación¶

    Son permisos asociados a operaciones que presentan un riesgo reducido para la privacidad del usuario o que cumplen determinadas condiciones establecidas por Android.

    Cuando una aplicación los declara correctamente, el sistema puede concederlos automáticamente sin mostrar un diálogo de autorización al usuario.

    Dentro de esta categoría destacan los permisos normales y los permisos de firma.

    Permisos normales¶

    Los permisos normales permiten acceder a operaciones cuyo riesgo para la privacidad y seguridad del usuario se considera reducido.

    No requieren que el usuario pulse un botón para autorizarlos.

    Un ejemplo muy habitual es:

    <uses-permission android:name="android.permission.INTERNET" />

    Este permiso permite que la aplicación establezca conexiones de red.

    Por ejemplo, una aplicación que utilice Retrofit para consultar una API REST necesitará normalmente:

    <manifest ...>

    <uses-permission android:name="android.permission.INTERNET" />

    <application
        ...>

    </application>

</manifest>

    Ejemplo

    Una aplicación que consulta información de libros desde una API REST necesita acceder a Internet.

    El permiso se declara en AndroidManifest.xml, pero Android no muestra un diálogo al usuario preguntando si quiere permitir el acceso a Internet.

    Permisos de firma¶

    Los permisos de firma se conceden únicamente cuando la aplicación que solicita el permiso está firmada con el certificado requerido por la aplicación o componente que define dicho permiso.

    Se utilizan principalmente para proteger comunicaciones entre aplicaciones relacionadas o determinadas funciones especialmente sensibles.

    Son menos habituales en aplicaciones Android convencionales.

    2. Permisos de tiempo de ejecución¶

    Los permisos asociados a datos o recursos especialmente sensibles necesitan autorización explícita del usuario.

    También reciben habitualmente el nombre de runtime permissions.

    Algunos ejemplos son:

    • Cámara.
    • Micrófono.
    • Ubicación.
    • Contactos.
    • Determinadas funciones de dispositivos cercanos.
    • Notificaciones en versiones recientes de Android.

    El proceso general es:

    La aplicación no debe asumir que un permiso seguirá concedido permanentemente.

    Debe comprobar su estado antes de utilizar el recurso protegido.

    Ejemplo: permiso de cámara¶

    Supongamos que queremos utilizar la cámara.

    Primero declaramos el permiso en:

    AndroidManifest.xml

    <uses-permission android:name="android.permission.CAMERA" />

    Después debemos comprobar durante la ejecución si el usuario ha concedido el permiso.

    Forma clásica¶

    Una forma tradicional de comprobar el permiso consiste en utilizar ContextCompat.checkSelfPermission():

    if (
    ContextCompat.checkSelfPermission(
        this,
        Manifest.permission.CAMERA
    ) == PackageManager.PERMISSION_GRANTED
) {
    // El permiso está concedido
    abrirCamara()
} else {
    // El permiso no está concedido
}

    La comprobación devuelve:

    PackageManager.PERMISSION_GRANTED

    cuando el permiso está concedido.

    Solicitud clásica del permiso¶

    Tradicionalmente también se podía solicitar mediante:

    ActivityCompat.requestPermissions(
    this,
    arrayOf(Manifest.permission.CAMERA),
    100
)

    El valor:

    100

    es un identificador utilizado para reconocer posteriormente la solicitud.

    Código heredado

    requestPermissions() aparece todavía en numerosos proyectos y tutoriales antiguos.

    En aplicaciones modernas resulta preferible utilizar las Activity Result APIs.

    Solicitud moderna con Activity Result API¶

    Una forma moderna de gestionar permisos consiste en utilizar:

    registerForActivityResult()

    junto con:

    ActivityResultContracts.RequestPermission()

    Ejemplo:

    private val solicitarPermisoCamara =
    registerForActivityResult(
        ActivityResultContracts.RequestPermission()
    ) { concedido ->

        if (concedido) {
            abrirCamara()
        } else {
            // El usuario ha rechazado el permiso
        }
    }

    Cuando queramos solicitar el permiso:

    solicitarPermisoCamara.launch(
    Manifest.permission.CAMERA
)

    El resultado se recibe mediante:

    concedido

    que será:

    true  → permiso concedido
false → permiso rechazado

    Permisos con Jetpack Compose¶

    En una aplicación desarrollada con Jetpack Compose, podemos utilizar igualmente las Activity Result APIs.

    Por ejemplo:

    @Composable
fun PantallaCamara() {

    val context = LocalContext.current

    val permisoCamara = rememberLauncherForActivityResult(
        contract = ActivityResultContracts.RequestPermission()
    ) { concedido ->

        if (concedido) {
            // Ya podemos utilizar la cámara
        }
    }

    Button(
        onClick = {
            permisoCamara.launch(
                Manifest.permission.CAMERA
            )
        }
    ) {
        Text("Abrir cámara")
    }
}

    Pero este código todavía puede mejorarse comprobando primero si el permiso ya está concedido:

    @Composable
fun PantallaCamara() {

    val context = LocalContext.current

    val permisoCamara = rememberLauncherForActivityResult(
        contract = ActivityResultContracts.RequestPermission()
    ) { concedido ->

        if (concedido) {
            // Abrir cámara
        }
    }

    Button(
        onClick = {

            val concedido = ContextCompat.checkSelfPermission(
                context,
                Manifest.permission.CAMERA
            ) == PackageManager.PERMISSION_GRANTED

            if (concedido) {
                // Abrir cámara
            } else {
                permisoCamara.launch(
                    Manifest.permission.CAMERA
                )
            }
        }
    ) {
        Text("Abrir cámara")
    }
}

    Ejemplo: permiso de micrófono¶

    Para grabar audio necesitamos declarar:

    <uses-permission android:name="android.permission.RECORD_AUDIO" />

    Después podemos solicitarlo mediante:

    val solicitarMicrofono = rememberLauncherForActivityResult(
    contract = ActivityResultContracts.RequestPermission()
) { concedido ->

    if (concedido) {
        // Comenzar grabación
    }
}

    Y lanzarlo mediante:

    solicitarMicrofono.launch(
    Manifest.permission.RECORD_AUDIO
)

    Buena práctica

    Una aplicación de mensajería que permite enviar notas de voz no debería solicitar acceso al micrófono al arrancar.

    El permiso debería solicitarse cuando el usuario pulsa por primera vez el botón Grabar audio.

    Ejemplo: permiso de ubicación¶

    Para obtener una ubicación aproximada podemos declarar:

    <uses-permission
    android:name="android.permission.ACCESS_COARSE_LOCATION" />

    Para una ubicación más precisa:

    <uses-permission
    android:name="android.permission.ACCESS_FINE_LOCATION" />

    Por ejemplo:

    val solicitarUbicacion = rememberLauncherForActivityResult(
    contract = ActivityResultContracts.RequestPermission()
) { concedido ->

    if (concedido) {
        // Acceder a la ubicación
    }
}

    Solicitud:

    solicitarUbicacion.launch(
    Manifest.permission.ACCESS_FINE_LOCATION
)

    Ubicación aproximada y precisa

    En versiones modernas de Android, el usuario dispone de mayor control sobre la precisión de la ubicación proporcionada a las aplicaciones.

    Una aplicación debe funcionar con ubicación aproximada siempre que no necesite realmente conocer la posición exacta del usuario.

    Solicitar varios permisos¶

    Algunas operaciones necesitan comprobar más de un permiso.

    Para estos casos podemos utilizar:

    ActivityResultContracts.RequestMultiplePermissions()

    Por ejemplo:

    val solicitarPermisos = rememberLauncherForActivityResult(
    contract = ActivityResultContracts.RequestMultiplePermissions()
) { permisos ->

    val camaraConcedida =
        permisos[Manifest.permission.CAMERA] ?: false

    val microfonoConcedido =
        permisos[Manifest.permission.RECORD_AUDIO] ?: false

    if (camaraConcedida && microfonoConcedido) {
        // Podemos utilizar cámara y micrófono
    }
}

    La solicitud se realiza mediante:

    solicitarPermisos.launch(
    arrayOf(
        Manifest.permission.CAMERA,
        Manifest.permission.RECORD_AUDIO
    )
)

    Permiso para mostrar notificaciones¶

    Desde Android 13 (API 33), las aplicaciones necesitan solicitar permiso al usuario para enviar determinadas notificaciones.

    El permiso es:

    <uses-permission
    android:name="android.permission.POST_NOTIFICATIONS" />

    Antes de solicitarlo debemos comprobar la versión de Android:

    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {

    permisoNotificaciones.launch(
        Manifest.permission.POST_NOTIFICATIONS
    )
}

    Esto es necesario porque:

    POST_NOTIFICATIONS → Android 13 / API 33+

    3. Permisos especiales¶

    Existen operaciones especialmente sensibles que Android no gestiona mediante el diálogo habitual de permisos.

    Son los denominados permisos especiales.

    Pueden controlar operaciones como:

    • Mostrar contenido sobre otras aplicaciones.
    • Modificar determinados ajustes del sistema.
    • Acceder a determinados datos o funciones especialmente protegidos.
    • Instalar paquetes desde determinadas fuentes.

    En estos casos, normalmente el usuario debe acceder a una pantalla específica de Ajustes para conceder la autorización.

    Ejemplo: mostrar sobre otras aplicaciones¶

    El permiso se declara mediante:

    <uses-permission
    android:name="android.permission.SYSTEM_ALERT_WINDOW" />

    Podemos comprobar si está concedido:

    if (!Settings.canDrawOverlays(this)) {

    val intent = Intent(
        Settings.ACTION_MANAGE_OVERLAY_PERMISSION,
        Uri.parse("package:$packageName")
    )

    startActivity(intent)
}

    En este caso Android lleva al usuario a una pantalla de configuración del sistema.

    Warning

    Los permisos especiales deben utilizarse únicamente cuando sean imprescindibles para la funcionalidad principal de la aplicación.

    Grupos de permisos¶

    Android organiza determinados permisos relacionados dentro de grupos de permisos.

    Algunos ejemplos conceptuales son:

    Grupo Permisos relacionados
    Cámara Uso de la cámara
    Micrófono Grabación de audio
    Ubicación Ubicación aproximada y precisa
    Contactos Lectura y modificación de contactos
    Calendario Lectura y modificación del calendario

    Los grupos ayudan al sistema a organizar y presentar los permisos relacionados.

    No depender de los grupos

    Una aplicación no debe asumir que obtener un permiso implica automáticamente disponer de todos los permisos pertenecientes al mismo grupo.

    El código debe comprobar individualmente los permisos que realmente necesita.

    ¿Qué ocurre si el usuario rechaza un permiso?¶

    El usuario siempre puede decidir:

    • Conceder el permiso.
    • Rechazarlo.
    • Conceder determinadas modalidades limitadas cuando Android las permita.
    • Revocarlo posteriormente desde los ajustes del dispositivo.

    Por tanto, nuestra aplicación debe estar preparada para continuar funcionando cuando un permiso sea rechazado.

    if (concedido) {

    abrirCamara()

} else {

    // Informar al usuario
    // y mantener funcionando el resto de la aplicación
}

    Nunca asumir que el usuario concederá el permiso

    Rechazar un permiso no debería provocar que la aplicación se cierre.

    Debe deshabilitarse únicamente la funcionalidad que depende de dicho permiso.

    Explicar por qué necesitamos un permiso¶

    En determinadas situaciones conviene explicar al usuario por qué una función necesita acceder a un recurso protegido.

    Android permite comprobarlo mediante:

    ActivityCompat.shouldShowRequestPermissionRationale(
    activity,
    Manifest.permission.CAMERA
)

    Podemos utilizarlo para mostrar un mensaje como:

    Necesitamos acceder a la cámara para poder escanear
el código QR del producto.

    Después, si el usuario decide continuar, solicitamos el permiso.

    Contexto antes que permiso

    Es mejor:

    Escanear QR → explicar necesidad → solicitar cámara

    que:

    Abrir aplicación → solicitar cámara sin explicación

    Buenas prácticas¶

    Solicitar el mínimo número de permisos¶

    Una aplicación debe solicitar únicamente los permisos imprescindibles.

    Por ejemplo, una aplicación que muestra información obtenida mediante una API REST probablemente solo necesite:

    <uses-permission android:name="android.permission.INTERNET" />

    No debería solicitar:

    Cámara
Micrófono
Contactos
Ubicación

    si no utiliza esas funcionalidades.

    Solicitar el permiso en contexto¶

    El permiso debería solicitarse cuando el usuario intenta utilizar la funcionalidad relacionada.

    Ofrecer alternativas¶

    Siempre que sea posible, la aplicación debe permitir realizar una acción sin acceder directamente a datos protegidos.

    Por ejemplo, en determinadas situaciones podemos utilizar un Photo Picker proporcionado por Android para que sea el propio usuario quien seleccione las imágenes que desea compartir con la aplicación.

    Esto evita solicitar acceso general a todas sus fotografías.

    Control y transparencia¶

    El usuario debe conocer:

    • Qué información utiliza la aplicación.
    • Por qué necesita esa información.
    • Para qué será utilizada.
    • Qué funcionalidad dejará de estar disponible si rechaza el permiso.

    Minimización de datos¶

    La aplicación debe acceder únicamente a los datos estrictamente necesarios.

    Por ejemplo:

    Necesidad: mostrar restaurantes cercanos

    puede justificar utilizar ubicación mientras el usuario utiliza esa funcionalidad.

    Pero no implica necesariamente:

    Acceder permanentemente a la ubicación
        +
Registrar todos los desplazamientos
        +
Mantener ubicación en segundo plano

    Permisos y componentes de Android¶

    Los permisos no solo sirven para controlar el acceso del usuario a determinados recursos.

    También pueden utilizarse para proteger componentes de una aplicación frente a otras aplicaciones.

    Los principales componentes Android son:

    • Activity.
    • Service.
    • BroadcastReceiver.
    • ContentProvider.

    Por ejemplo, podemos controlar si una Activity puede ser utilizada desde otra aplicación mediante:

    <activity
    android:name=".MainActivity"
    android:exported="false" />

    Con:

    android:exported="false"

    el componente no queda disponible para otras aplicaciones.

    Cuando un componente necesita ser accesible externamente, debemos analizar cuidadosamente qué aplicaciones deberían poder utilizarlo y qué mecanismos de seguridad necesita.

    Resumen¶

    Tipo ¿Usuario interviene? Ejemplo
    Normal No INTERNET
    Runtime Sí CAMERA
    Runtime Sí RECORD_AUDIO
    Runtime Sí ACCESS_FINE_LOCATION
    Runtime Sí POST_NOTIFICATIONS
    Especial Ajustes del sistema SYSTEM_ALERT_WINDOW
    Firma No normalmente Comunicación entre apps firmadas adecuadamente
