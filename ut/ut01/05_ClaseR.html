    La clase R¶

    En Android, la clase R es una clase generada automáticamente durante el proceso de compilación que permite acceder desde el código a los recursos de la aplicación.

    Los recursos se encuentran principalmente dentro de la carpeta:

    app/
└── src/
    └── main/
        ├── java/
        ├── res/
        │   ├── drawable/
        │   ├── layout/
        │   ├── mipmap/
        │   ├── values/
        │   ├── font/
        │   └── ...
        └── AndroidManifest.xml

    Android procesa los recursos almacenados en res/ y genera identificadores que quedan organizados dentro de la clase R.

    Importante

    La clase R no se crea ni se modifica manualmente. Forma parte del código generado automáticamente durante la compilación del proyecto.

    ¿Para qué sirve la clase R?¶

    La clase R actúa como un puente entre los recursos almacenados en res/ y el código Kotlin o Java de nuestra aplicación.

    Por ejemplo, podemos tener una cadena de texto definida en:

    res/values/strings.xml

    <resources>
    <string name="app_name">Mi aplicación</string>
    <string name="mensaje_bienvenida">Bienvenido a Android</string>
</resources>

    Android genera un identificador para cada recurso.

    Conceptualmente, podemos imaginar que la clase R contiene algo similar a:

    class R {

    class string {
        companion object {
            const val app_name = ...
            const val mensaje_bienvenida = ...
        }
    }
}

    Este código es únicamente una representación conceptual. No debemos crear esta clase manualmente.

    Desde Kotlin podemos acceder al recurso mediante:

    R.string.mensaje_bienvenida

    Por tanto:

    res/values/strings.xml
        │
        ▼
mensaje_bienvenida
        │
        ▼
R.string.mensaje_bienvenida
        │
        ▼
Código Kotlin

    Generación automática de R¶

    Durante la compilación, las herramientas de Android procesan los recursos de la aplicación y generan sus correspondientes identificadores.

    Por ejemplo, si tenemos:

    res/drawable/logo.png

    podremos acceder al recurso mediante:

    R.drawable.logo

    Si tenemos:

    res/layout/activity_main.xml

    podremos acceder mediante:

    R.layout.activity_main

    Y si tenemos:

    <string name="titulo">Mi aplicación</string>

    podremos utilizar:

    R.string.titulo

    El programador trabaja con estos nombres en lugar de utilizar directamente rutas de archivos.

    Estructura de la clase R¶

    Los identificadores están organizados según el tipo de recurso.

    Recurso Carpeta / archivo Acceso desde R
    Layout res/layout/ R.layout.nombre
    Imagen res/drawable/ R.drawable.nombre
    Texto res/values/strings.xml R.string.nombre
    Color res/values/colors.xml R.color.nombre
    Dimensión res/values/dimens.xml R.dimen.nombre
    Identificador android:id R.id.nombre
    Menú res/menu/ R.menu.nombre
    Fuente res/font/ R.font.nombre
    Animación res/anim/ R.anim.nombre
    Iconos de aplicación res/mipmap/ R.mipmap.nombre
    Estilos res/values/ R.style.nombre

    La sintaxis general es:

    R.tipo.nombre

    Por ejemplo:

    R.layout.activity_main
R.id.btnAceptar
R.string.app_name
R.drawable.logo
R.color.primary

    Ejemplo completo con XML¶

    Supongamos que tenemos el siguiente proyecto:

    res/
├── drawable/
│   └── logo_android.png
│
├── layout/
│   └── activity_main.xml
│
└── values/
    ├── colors.xml
    └── strings.xml

    strings.xml¶

    <resources>
    <string name="app_name">Clase R</string>
    <string name="mensaje">Aprendiendo recursos en Android</string>
    <string name="boton_aceptar">Aceptar</string>
</resources>

    Android permite acceder a estos recursos mediante:

    R.string.app_name
R.string.mensaje
R.string.boton_aceptar

    Layout¶

    En activity_main.xml:

    <?xml version="1.0" encoding="utf-8"?>

<LinearLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical">

    <TextView
        android:id="@+id/txtMensaje"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="@string/mensaje" />

    <ImageView
        android:id="@+id/imgLogo"
        android:layout_width="150dp"
        android:layout_height="150dp"
        android:src="@drawable/logo_android" />

    <Button
        android:id="@+id/btnAceptar"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="@string/boton_aceptar" />

</LinearLayout>

    Aquí aparecen varios tipos de recursos:

    @+id/txtMensaje
@+id/imgLogo
@+id/btnAceptar

@string/mensaje
@string/boton_aceptar

@drawable/logo_android

    Acceso desde Kotlin¶

    En una Activity tradicional podemos cargar el layout:

    class MainActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        setContentView(R.layout.activity_main)
    }
}

    La expresión:

    R.layout.activity_main

    hace referencia al archivo:

    res/layout/activity_main.xml

    Acceder a una vista¶

    Podemos acceder a una vista mediante su identificador:

    val boton = findViewById<Button>(R.id.btnAceptar)

    R.id.btnAceptar corresponde al identificador definido en XML:

    android:id="@+id/btnAceptar"

    Otro ejemplo:

    val texto = findViewById<TextView>(R.id.txtMensaje)

texto.text = "Hola Android"

    En proyectos actuales basados en XML suele utilizarse View Binding en lugar de abusar de findViewById(), pero R.id sigue siendo fundamental para comprender cómo Android identifica los recursos.

    Obtener una cadena de texto¶

    Supongamos:

    <string name="mensaje">Aprendiendo Android</string>

    Podemos recuperarla desde Kotlin mediante:

    val mensaje = getString(R.string.mensaje)

    La variable mensaje contendrá:

    Aprendiendo Android

    Esto es diferente de:

    val mensaje = R.string.mensaje

    En este segundo caso no obtenemos directamente el texto.

    R.string.mensaje representa el identificador del recurso.

    Por tanto:

    val id = R.string.mensaje

    almacena un identificador numérico generado por Android.

    Mientras que:

    val texto = getString(R.string.mensaje)

    obtiene el contenido real del recurso.

    Error frecuente

    R.string.mensaje no contiene directamente "Aprendiendo Android". Contiene un identificador que Android utiliza para localizar ese recurso.

    Recursos parametrizados¶

    Una ventaja importante de strings.xml es que podemos crear textos con parámetros.

    <string name="bienvenida">Bienvenido, %1$s</string>

    Después:

    val nombre = "Ana"

val mensaje = getString(
    R.string.bienvenida,
    nombre
)

    El resultado será:

    Bienvenido, Ana

    Esto evita construir textos manualmente:

    "Bienvenido, " + nombre

    y facilita la internacionalización de la aplicación.

    La clase R y Jetpack Compose¶

    La clase R también se utiliza en aplicaciones modernas desarrolladas con Jetpack Compose.

    Aunque Compose no utiliza archivos XML para crear normalmente la interfaz, sigue utilizando el sistema de recursos de Android.

    Por ejemplo:

    <string name="titulo">Mi aplicación</string>

    En Compose:

    Text(
    text = stringResource(R.string.titulo)
)

    Para una imagen:

    Image(
    painter = painterResource(R.drawable.logo_android),
    contentDescription = null
)

    Para un color:

    val color = colorResource(R.color.primary)

    Por tanto, Compose elimina gran parte de la necesidad de:

    R.layout
R.id

    pero sigue utilizando frecuentemente:

    R.string
R.drawable
R.color
R.font
R.dimen

    Ejemplo con Jetpack Compose¶

    Supongamos:

    res/
├── drawable/
│   └── logo_android.png
│
└── values/
    └── strings.xml

    Con:

    <resources>

    <string name="app_name">Mi aplicación</string>

    <string name="mensaje_bienvenida">
        Bienvenido a Android
    </string>

</resources>

    Podemos crear:

    @Composable
fun PantallaPrincipal() {

    Column {

        Text(
            text = stringResource(
                R.string.mensaje_bienvenida
            )
        )

        Image(
            painter = painterResource(
                R.drawable.logo_android
            ),
            contentDescription = null
        )
    }
}

    La relación sería:

    res/
 │
 ├── values/strings.xml
 │       │
 │       └── mensaje_bienvenida
 │                 │
 │                 ▼
 │       R.string.mensaje_bienvenida
 │                 │
 │                 ▼
 │          stringResource()
 │
 └── drawable/logo_android.png
         │
         ▼
 R.drawable.logo_android
         │
         ▼
   painterResource()

    Nombres de los recursos¶

    Los nombres de los recursos deben seguir las reglas establecidas por Android.

    Normalmente se utiliza:

    snake_case

    Ejemplos correctos:

    logo_android.png
icono_usuario.xml
activity_main.xml
imagen_perfil.jpg

    Y nombres como:

    logoAndroid.png
LogoAndroid.png
logo-android.png

    no son adecuados como nombres de recursos Android.

    Esto permite generar identificadores válidos como:

    R.drawable.logo_android

    ¿Qué ocurre si eliminamos un recurso?¶

    Supongamos que tenemos:

    res/drawable/logo_android.png

    y utilizamos:

    R.drawable.logo_android

    Si eliminamos el archivo:

    logo_android.png

    el identificador dejará de estar disponible.

    El código:

    R.drawable.logo_android

    producirá entonces un error de compilación.

    Esto permite detectar rápidamente referencias a recursos que ya no existen.

    Errores relacionados con R¶

    Uno de los problemas clásicos en Android es que aparezca un error como:

    Unresolved reference: R

    o:

    Cannot resolve symbol R

    Esto no significa necesariamente que exista un problema con la clase R.

    Normalmente indica que Android no ha podido procesar correctamente algún recurso del proyecto.

    Algunas causas habituales son:

    • Error en un archivo XML.
    • Nombre de recurso no válido.
    • Referencia a un recurso inexistente.
    • Problemas durante la sincronización de Gradle.
    • Error en la configuración del módulo.
    • Importación incorrecta de otra clase R.

    Por ejemplo, debe evitarse importar accidentalmente:

    import android.R

    porque esa clase contiene los recursos del propio sistema Android, no los recursos de nuestra aplicación.

    En nuestro código normalmente trabajaremos con la R correspondiente al paquete o namespace de nuestra aplicación.

    Recursos de Android frente a recursos de nuestra aplicación¶

    Existen recursos proporcionados por el propio sistema Android.

    Se accede a ellos mediante:

    android.R

    Por ejemplo:

    android.R.string.ok

    Mientras que los recursos propios utilizan:

    R.string.nombre

    Por tanto:

    R
│
└── Recursos de nuestra aplicación

android.R
│
└── Recursos proporcionados por Android

    La clase R y los módulos¶

    En proyectos Android grandes podemos tener varios módulos:

    Proyecto
│
├── app
├── feature_login
├── feature_profile
└── core

    Cada módulo Android puede generar su propia clase R asociada a los recursos que le corresponden.

    Esto es especialmente importante cuando trabajamos con:

    • aplicaciones modulares;
    • bibliotecas Android;
    • arquitecturas grandes;
    • módulos de funcionalidades.

    Esquema general¶

    El funcionamiento de la clase R puede resumirse así:

                   RECURSOS

                   res/
                    │
        ┌───────────┼───────────┐
        │           │           │
     layout      drawable     values
        │           │           │
        ▼           ▼           ▼
 activity_main   logo.png   strings.xml
        │           │           │
        └───────────┼───────────┘
                    │
                    ▼
          Procesamiento de recursos
                    │
                    ▼
                 Clase R
                    │
        ┌───────────┼────────────┐
        │           │            │
    R.layout    R.drawable    R.string
        │           │            │
        ▼           ▼            ▼
activity_main     logo          titulo
                    │
                    ▼
               Código Kotlin

    Resumen¶

    La clase R:

    • Se genera automáticamente durante el proceso de compilación.
    • Representa los recursos disponibles para el código Android.
    • No debe modificarse manualmente.
    • Organiza los recursos por tipos.
    • Utiliza la sintaxis:
    R.tipo.nombre

    Ejemplos:

    R.string.titulo
R.drawable.logo
R.color.primary
R.layout.activity_main
R.id.btnAceptar

    En aplicaciones tradicionales basadas en XML son especialmente importantes:

    R.layout
R.id

    En aplicaciones desarrolladas con Jetpack Compose son especialmente habituales:

    R.string
R.drawable
R.color
R.font
R.dimen

    La idea fundamental es:

    Recurso almacenado en res/
          ↓
Android genera un identificador
          ↓
R.tipo.nombre
          ↓
El código Kotlin utiliza el recurso

    Ejemplos de uso¶

    Layout y vista principal

    // Enlazar la actividad con el layout definido en XML
setContentView(R.layout.activity_main);

    Cargar un recurso gráfico

    // Asignar una imagen a un ImageView
imageView.setImageResource(R.drawable.logo);

    Acceder a un texto definido en strings.xml

    // Obtener una cadena de texto
String saludo = getString(R.string.bienvenida);

    A lo largo del curso avanzaremos en ella, pero tienes una descripción general de los tipos de recursos que hacen uso de ella.
