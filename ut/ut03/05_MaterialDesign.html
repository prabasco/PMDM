    Material Design 3 en Android con Kotlin y Jetpack Compose¶

    1. Experiencia de usuario (UX) e interfaz de usuario (UI)¶

    • UI (User Interface): elementos visibles e interactivos: botones, campos de texto, colores, tipografías y distribución.
    • UX (User Experience): facilidad, claridad, eficiencia y satisfacción durante el uso de una aplicación. Incluye accesibilidad y respuesta a los errores.

    Ejemplo: un formulario puede tener una UI atractiva, pero ofrecer una UX deficiente si no explica por qué un correo es inválido o si pierde los datos al girar el dispositivo.

    En Android existen dos enfoques vigentes para construir pantallas:

    Vistas tradicionales Jetpack Compose
    Layouts XML y objetos View Funciones Kotlin @Composable
    Actualización imperativa de vistas Interfaz declarativa dependiente del estado
    Material Components for Android (MDC) Material 3 para Compose
    Reutilización mediante vistas personalizadas, layouts y fragments Reutilización mediante composables

    Distinción importante

    Material Design es un sistema de diseño; Jetpack Compose es un toolkit declarativo para crear UI. No son lo mismo. La separación entre UI y lógica de negocio sigue siendo recomendable en Compose: utiliza, cuando proceda, ViewModel, repositorios y elevación de estado.

    2. ¿Qué es Material Design 3?¶

    Material Design es el sistema de diseño desarrollado por Google que proporciona pautas de componentes, color, tipografía, formas, movimiento y accesibilidad. Material 3 es su evolución y ofrece componentes y esquemas de color preparados para diferentes dispositivos y temas.

    2.1. Material 2 frente a Material 3¶

    Aspecto Material 2 Material 3
    Paquete Compose androidx.compose.material androidx.compose.material3
    Tema MaterialTheme de Material 2 MaterialTheme de Material 3
    Colores colors colorScheme
    Tipografía Escala de Material 2 Escala de Material 3
    Color dinámico No integrado como esquema estándar Disponible en Android 12+ (API 31+)
    Componentes Material 2 Variantes actualizadas y nuevos componentes

    No mezcles importaciones de androidx.compose.material.* con androidx.compose.material3.* sin una razón explícita. La existencia y estabilidad de un componente depende de la versión concreta de la biblioteca.

    2.2. Configuración en Android Studio¶

    Al crear un proyecto Empty Activity con Compose, Android Studio suele generar la configuración básica. Comprueba que el catálogo gradle/libs.versions.toml incluya el BOM de Compose y Material 3. Ejemplo orientativo (las versiones concretas se gestionan en el catálogo del proyecto):

    [libraries]
androidx-compose-bom = { group = "androidx.compose", name = "compose-bom", version.ref = "composeBom" }
androidx-material3 = { group = "androidx.compose.material3", name = "material3" }

    La clave composeBom debe existir en [versions] con una versión de BOM compatible. En app/build.gradle.kts:

    dependencies {
    implementation(platform(libs.androidx.compose.bom))
    implementation(libs.androidx.material3)
}

    El Compose BOM coordina versiones de bibliotecas Compose incluidas en él, pero no configura por sí mismo el plugin de Kotlin ni el compilador Compose. Sigue la plantilla de Android Studio y consulta configuración oficial y versiones de Material 3. No es correcto afirmar que omitir una versión siempre descarga «la última estable»: sin BOM ni otra restricción de versión, Gradle no dispone de una versión que resolver.

    3. Componentes principales¶

    Categoría Componentes Uso
    Acciones Button, OutlinedButton, TextButton, FloatingActionButton Ejecutar acciones
    Selección Checkbox, RadioButton, Switch, Slider Elegir valores
    Entrada TextField, OutlinedTextField Introducir texto
    Contenedores Card, ElevatedCard, Surface Agrupar contenido
    Opciones contextuales AssistChip, FilterChip, InputChip, SuggestionChip Sugerir o filtrar
    Comunicación Snackbar, LinearProgressIndicator, Badge Informar del estado
    Confirmación AlertDialog, Dialog Solicitar una decisión
    Estructura Scaffold, TopAppBar, NavigationBar Organizar pantallas

    Los componentes se utilizan dentro de funciones anotadas con @Composable y deben respetar el tema y la accesibilidad.

    4. Botones¶

    Documentación oficial

    • Button: acción principal.
    • OutlinedButton: acción secundaria.
    • FilledTonalButton: acción de énfasis intermedio.
    • TextButton: acción de baja prioridad, frecuente en diálogos.
    @Composable
fun EjemploBotones() {
    var mensaje by rememberSaveable { mutableStateOf("Sin acciones") }

    Column(
        modifier = Modifier.padding(16.dp),
        verticalArrangement = Arrangement.spacedBy(8.dp)
    ) {
        Text(mensaje)
        Button(onClick = { mensaje = "Guardado" }) { Text("Guardar") }
        OutlinedButton(onClick = { mensaje = "Cancelado" }) { Text("Cancelar") }
        FilledTonalButton(onClick = { mensaje = "Vista previa" }) {
            Text("Vista previa")
        }
    }
}

    onClick recibe una función lambda. Al cambiar mensaje, Compose recompone las partes de la UI que leen ese estado. Los parámetros opcionales de los botones, como colors, shape y contentPadding, tienen valores de diseño por defecto. Personalízalos solo cuando exista un requisito de diseño.

    5. Checkbox y elevación de estado¶

    Documentación oficial

    Un Checkbox permite seleccionar o deseleccionar una opción. Para elegir una única opción entre varias, suele corresponder RadioButton.

    @Composable
fun CheckboxConEtiqueta(
    texto: String,
    marcado: Boolean,
    onMarcadoChange: (Boolean) -> Unit
) {
    Row(verticalAlignment = Alignment.CenterVertically) {
        Checkbox(checked = marcado, onCheckedChange = onMarcadoChange)
        Text(texto)
    }
}

@Composable
fun EjemploCheckbox() {
    var aceptado by rememberSaveable { mutableStateOf(false) }
    Column(Modifier.padding(16.dp)) {
        CheckboxConEtiqueta(
            texto = "Acepto las condiciones",
            marcado = aceptado,
            onMarcadoChange = { aceptado = it }
        )
        Button(onClick = {}, enabled = aceptado) { Text("Continuar") }
    }
}

    CheckboxConEtiqueta es stateless: recibe el valor y comunica cambios mediante una función. El padre conserva el estado. Esta técnica se denomina state hoisting (elevación de estado) y facilita la reutilización y las pruebas. Para que toda la fila sea pulsable, hay que implementar la interacción accesible de forma coordinada, evitando dos controles semánticos duplicados.

    6. Cards: tarjetas de contenido¶

    Documentación oficial

    Una Card agrupa contenido relacionado: título, descripción, imagen y acciones. Sí pueden mostrarse muchas tarjetas en una lista; la tarjeta individual representa normalmente un elemento o unidad de información. Existen Card, ElevatedCard y OutlinedCard.

    @Composable
fun TarjetaCurso(nombre: String, descripcion: String) {
    ElevatedCard(
        modifier = Modifier.fillMaxWidth(),
        elevation = CardDefaults.elevatedCardElevation(defaultElevation = 4.dp)
    ) {
        Column(
            modifier = Modifier.padding(16.dp),
            verticalArrangement = Arrangement.spacedBy(8.dp)
        ) {
            Text(nombre, style = MaterialTheme.typography.titleLarge)
            Text(descripcion, style = MaterialTheme.typography.bodyMedium)
            Button(onClick = { /* Navegar al detalle */ }) {
                Text("Saber más")
            }
        }
    }
}

@Composable
fun EjemploTarjeta() {
    TarjetaCurso(
        "IES Las Espeñetas",
        "Ciclo formativo de Desarrollo de Aplicaciones Multiplataforma"
    )
}

    El botón ilustra dónde conectar una acción real; el comentario no implementa navegación. Las tarjetas clicables admiten variantes con onClick según la API disponible. No confundas Card con Surface: Surface es un contenedor general con propiedades visuales y semánticas.

    7. TextField y validación de formularios¶

    Documentación oficial

    • TextField: campo relleno.
    • OutlinedTextField: campo con contorno.
    • label: etiqueta persistente del campo.
    • placeholder: ejemplo o pista, no sustituye la etiqueta.
    • isError y supportingText: estado y explicación del error.
    • KeyboardOptions: tipo de teclado y acción IME.

    7.1. Ejemplo de formulario con validación¶

    @Composable
fun FormularioRegistro() {
    var nombre by rememberSaveable { mutableStateOf("") }
    var correo by rememberSaveable { mutableStateOf("") }
    var intentadoEnviar by rememberSaveable { mutableStateOf(false) }

    val nombreInvalido = nombre.isBlank()
    val correoInvalido = !android.util.Patterns.EMAIL_ADDRESS
        .matcher(correo.trim()).matches()

    Column(
        modifier = Modifier.padding(16.dp),
        verticalArrangement = Arrangement.spacedBy(12.dp)
    ) {
        OutlinedTextField(
            value = nombre,
            onValueChange = { nombre = it },
            label = { Text("Nombre") },
            singleLine = true,
            isError = intentadoEnviar && nombreInvalido,
            supportingText = {
                if (intentadoEnviar && nombreInvalido) {
                    Text("El nombre es obligatorio")
                }
            },
            modifier = Modifier.fillMaxWidth()
        )
        OutlinedTextField(
            value = correo,
            onValueChange = { correo = it },
            label = { Text("Correo electrónico") },
            placeholder = { Text("usuario@ejemplo.com") },
            singleLine = true,
            keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.Email),
            isError = intentadoEnviar && correoInvalido,
            supportingText = {
                if (intentadoEnviar && correoInvalido) {
                    Text("Introduce un correo válido")
                }
            },
            modifier = Modifier.fillMaxWidth()
        )
        Button(onClick = { intentadoEnviar = true }) {
            Text("Validar")
        }
        if (intentadoEnviar && !nombreInvalido && !correoInvalido) {
            Text("Formulario válido", color = MaterialTheme.colorScheme.primary)
        }
    }
}

    La comprobación mediante Patterns.EMAIL_ADDRESS es una validación básica de formato, no verifica que la dirección exista. Evitamos !! y validadores no definidos en el ejemplo. Para una aplicación real, valida también en el servidor. rememberSaveable conserva los valores guardables ante recreaciones habituales, como un giro de pantalla, y no sustituye el almacenamiento persistente.

    8. Chips: sugerencias y filtros¶

    Documentación oficial

    Tipo Finalidad
    AssistChip Ayudar a completar una tarea
    FilterChip Activar o desactivar un filtro
    InputChip Representar una entrada o selección del usuario
    SuggestionChip Proponer una acción contextual

    A diferencia de una regla absoluta, algunos chips también ejecutan acciones. Su función depende del tipo y del contexto.

    @Composable
fun FiltroCiclos() {
    var dam by rememberSaveable { mutableStateOf(false) }
    var daw by rememberSaveable { mutableStateOf(false) }

    Row(horizontalArrangement = Arrangement.spacedBy(8.dp)) {
        FilterChip(
            selected = dam,
            onClick = { dam = !dam },
            label = { Text("DAM") }
        )
        FilterChip(
            selected = daw,
            onClick = { daw = !daw },
            label = { Text("DAW") }
        )
    }
}

    El estado dam y daw debe utilizarse después para filtrar datos reales; aquí se muestra el funcionamiento visual de los chips.

    9. Diálogos y confirmaciones¶

    Documentación oficial

    AlertDialog se utiliza para decisiones importantes, como confirmar una eliminación. Dialog permite contenido personalizado. Evita diálogos para información trivial que pueda comunicarse sin interrumpir al usuario.

    @Composable
fun EjemploDialogo() {
    var mostrar by rememberSaveable { mutableStateOf(false) }
    var resultado by rememberSaveable { mutableStateOf("Ninguna acción") }

    Column(Modifier.padding(16.dp)) {
        Text(resultado)
        Button(onClick = { mostrar = true }) { Text("Eliminar registro") }
    }

    if (mostrar) {
        AlertDialog(
            onDismissRequest = { mostrar = false },
            title = { Text("Confirmar eliminación") },
            text = { Text("¿Quieres eliminar el registro?") },
            confirmButton = {
                TextButton(onClick = {
                    resultado = "Eliminación confirmada"
                    mostrar = false
                }) { Text("Eliminar") }
            },
            dismissButton = {
                TextButton(onClick = { mostrar = false }) {
                    Text("Cancelar")
                }
            }
        )
    }
}

    El ejemplo confirma visualmente la acción; no elimina ningún registro real. El estado mostrar se modifica fuera de la función que construye el diálogo. Evita operaciones aleatorias dentro de composables que pueden recomponerse: calcula la oferta al abrir el diálogo y conserva el resultado en estado si necesitas mantenerla estable.

    10. Snackbar y Scaffold¶

    Documentación oficial

    Snackbar comunica resultados breves y puede ofrecer una acción como Deshacer. Scaffold proporciona zonas estructurales para contenido, barras y snackbars.

    @Composable
fun EjemploSnackbar() {
    val snackbarHostState = remember { SnackbarHostState() }
    val scope = rememberCoroutineScope()

    Scaffold(
        snackbarHost = { SnackbarHost(snackbarHostState) }
    ) { innerPadding ->
        Box(
            modifier = Modifier
                .fillMaxSize()
                .padding(innerPadding),
            contentAlignment = Alignment.Center
        ) {
            Button(onClick = {
                scope.launch {
                    snackbarHostState.showSnackbar(
                        message = "Registro guardado",
                        actionLabel = "Deshacer"
                    )
                }
            }) {
                Text("Guardar")
            }
        }
    }
}

    En este ejemplo, Deshacer solo se muestra como etiqueta. Para revertir una operación real, analiza el SnackbarResult.ActionPerformed devuelto por showSnackbar() y ejecuta la reversión correspondiente. Importa kotlinx.coroutines.launch.

    11. Tematización: color, tipografía y modo oscuro¶

    MaterialTheme centraliza el aspecto visual. Sus propiedades más utilizadas son colorScheme, typography y shapes.

    @Composable
fun TemaAplicacion(content: @Composable () -> Unit) {
    val contexto = LocalContext.current
    val oscuro = isSystemInDarkTheme()

    val colores = if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
        if (oscuro) dynamicDarkColorScheme(contexto)
        else dynamicLightColorScheme(contexto)
    } else {
        if (oscuro) darkColorScheme() else lightColorScheme()
    }

    MaterialTheme(colorScheme = colores, content = content)
}

    Importaciones específicas: android.os.Build, androidx.compose.foundation.isSystemInDarkTheme, androidx.compose.ui.platform.LocalContext y las funciones de androidx.compose.material3.

    @Composable
fun TextoTematizado() {
    Text(
        "Bienvenido a DAM",
        color = MaterialTheme.colorScheme.primary,
        style = MaterialTheme.typography.headlineSmall
    )
}

    El color dinámico está disponible a partir de Android 12 (API 31). Los temas personalizados pueden utilizar esquemas fijos o dinámicos según el diseño del proyecto. Para pantallas grandes, consulta diseño adaptable.

    12. Estado, recomposición y giro de pantalla¶

    • remember: conserva el estado durante recomposiciones, pero no garantiza su conservación al recrearse la Activity.
    • rememberSaveable: guarda estados compatibles con el mecanismo de estado guardado y suele recuperarlos después de cambios de configuración.
    • Recomposición: Compose vuelve a ejecutar las funciones o regiones necesarias cuando cambia el estado leído por la UI.
    • State hoisting: el padre mantiene el estado y los hijos reciben valores y callbacks.
    • ViewModel: gestiona estado y lógica de pantalla de mayor complejidad; no sustituye automáticamente la persistencia tras finalizar el proceso.
    @Composable
fun ContadorPersistente() {
    var contador by rememberSaveable { mutableIntStateOf(0) }
    Column(Modifier.padding(16.dp)) {
        Text("Pulsaciones: $contador")
        Button(onClick = { contador++ }) { Text("Incrementar") }
    }
}

    Prueba: incrementa el contador, gira el emulador y verifica que se conserva. Repite el ejercicio sustituyendo rememberSaveable por remember y observa la diferencia al recrearse la Activity.

    13. Accesibilidad y buenas prácticas¶

    1. Utiliza etiquetas comprensibles y mensajes de error próximos al campo correspondiente.
    2. Mantén contraste suficiente y no comuniques errores únicamente mediante colores.
    3. Define contentDescription para imágenes e iconos informativos; usa null para imágenes puramente decorativas.
    4. Respeta el escalado de fuente y evita tamaños rígidos que recorten texto.
    5. Procura objetivos táctiles de al menos 48 × 48 dp para controles interactivos.
    6. Reutiliza colores, tipografía y formas de MaterialTheme.
    7. Prueba modo claro y oscuro, orientación vertical y horizontal y tamaños de pantalla diferentes.
    8. Evita mantener lógica de negocio compleja dentro de composables.

    14. Ejemplo integrador: pantalla de perfil¶

    El siguiente ejemplo combina Card, OutlinedTextField, Checkbox, Button, Scaffold y Snackbar.

    @Composable
fun PerfilScreen() {
    var correo by rememberSaveable { mutableStateOf("") }
    var aceptado by rememberSaveable { mutableStateOf(false) }
    val snackbarHostState = remember { SnackbarHostState() }
    val scope = rememberCoroutineScope()

    Scaffold(snackbarHost = { SnackbarHost(snackbarHostState) }) { padding ->
        Column(
            modifier = Modifier
                .fillMaxSize()
                .padding(padding)
                .padding(16.dp),
            verticalArrangement = Arrangement.spacedBy(12.dp)
        ) {
            ElevatedCard(Modifier.fillMaxWidth()) {
                Column(Modifier.padding(16.dp)) {
                    Text("Perfil del estudiante", style = MaterialTheme.typography.titleLarge)
                    Text("Estudiante DAM")
                }
            }
            OutlinedTextField(
                value = correo,
                onValueChange = { correo = it },
                label = { Text("Correo electrónico") },
                keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.Email),
                modifier = Modifier.fillMaxWidth()
            )
            CheckboxConEtiqueta(
                texto = "Acepto las condiciones",
                marcado = aceptado,
                onMarcadoChange = { aceptado = it }
            )
            Button(
                enabled = aceptado && android.util.Patterns.EMAIL_ADDRESS
                    .matcher(correo.trim()).matches(),
                onClick = {
                    scope.launch {
                        snackbarHostState.showSnackbar("Perfil validado")
                    }
                }
            ) { Text("Guardar perfil") }
        }
    }
}

    Este ejemplo no almacena datos en una base de datos. Para usarlo como pantalla inicial, llama a PerfilScreen() dentro de setContent { TemaAplicacion { PerfilScreen() } }.

    15. Actividades¶

    AC 310 · Componentes básicos (RA2 / CE2a / IC1 / 3 puntos)¶

    Crea un proyecto Compose y una función MainScreen() que muestre un título (Text), un botón (Button) que cambie el texto al pulsarlo y una tarjeta (Card) con la descripción de tu plato favorito. Conserva el mensaje tras el giro mediante rememberSaveable.

    Comprobación: el botón cambia el estado, la tarjeta presenta el contenido y el tema es coherente.

    PR 311 · Perfil de estudiante (RA2 / CE2a / IC2 / 5 puntos)¶

    Crea PerfilScreen() con una tarjeta que contenga nombre, avatar y rol «Estudiante DAM»; un OutlinedTextField editable para correo, un Checkbox para aceptar las condiciones y un botón que muestre un Snackbar. Valida el formato del correo, desactiva el botón cuando el formulario no sea válido y conserva los datos al girar el dispositivo.

    PR 312 · Catálogo de productos (RA2 / CE2a / IC2 / 5 puntos)¶

    Define un modelo Producto con nombre, imagen, categoría y precio. Presenta varios productos mediante LazyColumn o LazyVerticalGrid. Cada elemento debe mostrarse en una Card con imagen, nombre, precio y botón «Ver más». Incorpora al menos dos FilterChip para filtrar por categoría y un estado vacío cuando no haya coincidencias.

    PR 313 · Formulario de acceso (RA2 / CE2a / IC2 / 5 puntos)¶

    Crea LoginScreen() con campos de correo y contraseña, validación de campos vacíos y formato de correo, botón de inicio de sesión y Snackbar o AlertDialog para informar del resultado. La contraseña debe utilizar PasswordVisualTransformation y el teclado apropiado. Simula el inicio de sesión sin enviar contraseñas a un servicio real.

    Evaluación

    Se valorará el funcionamiento, la correcta gestión del estado, la accesibilidad básica, la reutilización de componentes, la validación y la coherencia con Material 3. Las etiquetas RA/CE/IC y las puntuaciones se conservan del documento de partida; su correspondencia oficial debe verificarse con la programación didáctica.
