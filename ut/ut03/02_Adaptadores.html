    Adaptadores en Android¶

    1. ¿Qué es un adaptador?¶

    Un adaptador conecta una fuente de datos (por ejemplo, una lista de objetos Kotlin) con un componente visual que muestra esos datos. En la interfaz clásica de Android, ListView solicita al adaptador las vistas que representan cada elemento.

    El adaptador permite separar datos y presentación: los datos pueden cambiar sin que tengamos que construir manualmente todas las filas.

    flowchart LR
    A[Lista de datos] --> B[Adapter]
    B --> C[ListView]
    C --> D[Filas visibles]

    Android actual

    ListView y sus adaptadores siguen disponibles. En interfaces basadas en vistas se suele preferir RecyclerView; en proyectos con Jetpack Compose se utilizan LazyColumn y LazyRow, sin necesidad de crear un Adapter clásico.

    2. Funcionamiento de ListView¶

    ListView consulta al adaptador cuántos elementos existen y solicita las vistas necesarias para mostrar la zona visible. Al desplazarse, puede reutilizar vistas antiguas para evitar crearlas continuamente.

    Método Función
    getCount() Número de elementos disponibles.
    getItem(position) Obtiene el dato de una posición.
    getItemId(position) Devuelve el identificador Long de un elemento.
    getView(position, convertView, parent) Proporciona la vista de la fila; puede reutilizar convertView.

    Estos métodos pertenecen a la API de adaptadores clásicos. En ArrayAdapter varios ya están implementados; no es necesario sobrescribirlos para una lista sencilla.

    3. Primer ejemplo: ArrayAdapter con cadenas¶

    Vamos a mostrar nombres de lenguajes en una lista. Este ejemplo utiliza Kotlin y XML, no Jetpack Compose.

    3.1. Diseño de la actividad¶

    Archivo res/layout/activity_main.xml:

    <?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:padding="16dp">

    <ListView
        android:id="@+id/listaLenguajes"
        android:layout_width="match_parent"
        android:layout_height="match_parent" />
</LinearLayout>

    3.2. Código de la actividad¶

    Archivo MainActivity.kt (ajusta el paquete al de tu proyecto):

    import android.app.Activity
import android.os.Bundle
import android.widget.ArrayAdapter
import android.widget.ListView
import android.widget.Toast

class MainActivity : Activity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        val lenguajes = listOf("Kotlin", "Java", "Python", "C#")
        val lista = findViewById<ListView>(R.id.listaLenguajes)

        val adaptador = ArrayAdapter(
            this,
            android.R.layout.simple_list_item_1,
            lenguajes
        )
        lista.adapter = adaptador

        lista.setOnItemClickListener { _, _, position, _ ->
            Toast.makeText(
                this,
                "Seleccionado: ${lenguajes[position]}",
                Toast.LENGTH_SHORT
            ).show()
        }
    }
}

    Explicación: simple_list_item_1 es un diseño de fila incluido en Android que contiene un TextView. ArrayAdapter transforma cada cadena en el texto de una fila. setOnItemClickListener permite detectar qué elemento ha pulsado el usuario.

    Comprobación

    Ejecuta la aplicación y pulsa una fila. Comprueba que el mensaje cambia según el elemento seleccionado.

    4. Mostrar objetos: adaptador personalizado¶

    Cuando una fila debe mostrar varios datos (por ejemplo, nombre y horas de un módulo), conviene definir un diseño propio y un adaptador personalizado.

    4.1. Modelo de datos¶

    Archivo Modulo.kt:

    data class Modulo(
    val nombre: String,
    val horas: Int
)

    4.2. Diseño de cada fila¶

    Archivo res/layout/item_modulo.xml:

    <?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:orientation="vertical"
    android:padding="12dp">

    <TextView
        android:id="@+id/txtNombre"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:textSize="18sp" />

    <TextView
        android:id="@+id/txtHoras"
        android:layout_width="match_parent"
        android:layout_height="wrap_content" />
</LinearLayout>

    4.3. Implementación con BaseAdapter¶

    Archivo ModuloAdapter.kt:

    import android.content.Context
import android.view.LayoutInflater
import android.view.View
import android.view.ViewGroup
import android.widget.BaseAdapter
import android.widget.TextView

class ModuloAdapter(
    private val contexto: Context,
    private val modulos: List<Modulo>
) : BaseAdapter() {

    override fun getCount(): Int = modulos.size

    override fun getItem(position: Int): Modulo = modulos[position]

    override fun getItemId(position: Int): Long = position.toLong()

    override fun getView(
        position: Int,
        convertView: View?,
        parent: ViewGroup
    ): View {
        val vista = convertView ?: LayoutInflater.from(contexto)
            .inflate(R.layout.item_modulo, parent, false)

        val modulo = getItem(position)
        vista.findViewById<TextView>(R.id.txtNombre).text = modulo.nombre
        vista.findViewById<TextView>(R.id.txtHoras).text =
            "Duración: ${modulo.horas} horas"

        return vista
    }
}

    ¿Qué hace convertView? Si es null, creamos una fila inflando el XML. Si no lo es, reutilizamos la vista recibida y actualizamos su contenido. Esto reduce la creación de objetos durante el desplazamiento.

    Identificadores

    En este ejemplo getItemId() utiliza la posición por simplicidad. En listas con elementos que se insertan, eliminan o reordenan, la posición no es un identificador estable: es preferible usar un ID propio si se necesita identidad estable.

    4.4. Utilizar el adaptador¶

    Sustituye el contenido de onCreate() del primer ejemplo, manteniendo setContentView():

    val modulos = listOf(
    Modulo("Programación", 256),
    Modulo("Bases de Datos", 192),
    Modulo("Entornos de Desarrollo", 96)
)

val lista = findViewById<ListView>(R.id.listaLenguajes)
lista.adapter = ModuloAdapter(this, modulos)

    Las horas son datos de ejemplo, no una referencia curricular oficial.

    5. Actualizar los datos de una lista¶

    Si los datos cambian, la interfaz debe recibir una notificación para actualizar las filas.

    Ejemplo con ArrayAdapter y una lista mutable:

    val lenguajes = mutableListOf("Kotlin", "Java")
val adaptador = ArrayAdapter(
    this,
    android.R.layout.simple_list_item_1,
    lenguajes
)
lista.adapter = adaptador

// Añadimos un nuevo elemento mediante el adaptador.
adaptador.add("Python")

    ArrayAdapter tiene activada por defecto la notificación automática de cambios al utilizar métodos como add(). Si se modifica directamente una colección mutable que sirve de fuente de datos, puede ser necesario llamar a notifyDataSetChanged().

    6. RecyclerView: alternativa moderna basada en vistas¶

    RecyclerView separa varias responsabilidades:

    • RecyclerView: contenedor que muestra los elementos.
    • RecyclerView.Adapter: crea y vincula los elementos visuales con los datos.
    • ViewHolder: conserva referencias a las vistas de una fila.
    • LayoutManager: organiza los elementos (lista vertical, horizontal o cuadrícula).
    flowchart TD
    A[Lista de módulos] --> B[RecyclerView.Adapter]
    B --> C[ViewHolder]
    C --> D[RecyclerView]
    E[LinearLayoutManager] --> D

    Para utilizarlo, incorpora la dependencia androidx.recyclerview:recyclerview con una versión compatible con tu proyecto.

    Ejemplo mínimo de adaptador RecyclerView¶

    Reutilizaremos Modulo y item_modulo.xml:

    import android.view.LayoutInflater
import android.view.View
import android.view.ViewGroup
import android.widget.TextView
import androidx.recyclerview.widget.RecyclerView

class ModuloRecyclerAdapter(private val modulos: List<Modulo>) :
    RecyclerView.Adapter<ModuloRecyclerAdapter.ModuloViewHolder>() {

    class ModuloViewHolder(vista: View) : RecyclerView.ViewHolder(vista) {
        val nombre: TextView = vista.findViewById(R.id.txtNombre)
        val horas: TextView = vista.findViewById(R.id.txtHoras)
    }

    override fun onCreateViewHolder(parent: ViewGroup, viewType: Int): ModuloViewHolder {
        val vista = LayoutInflater.from(parent.context)
            .inflate(R.layout.item_modulo, parent, false)
        return ModuloViewHolder(vista)
    }

    override fun onBindViewHolder(holder: ModuloViewHolder, position: Int) {
        val modulo = modulos[position]
        holder.nombre.text = modulo.nombre
        holder.horas.text = "Duración: ${modulo.horas} horas"
    }

    override fun getItemCount(): Int = modulos.size
}

    Diseño activity_main.xml para este ejemplo:

    <?xml version="1.0" encoding="utf-8"?>
<androidx.recyclerview.widget.RecyclerView
    xmlns:android="http://schemas.android.com/apk/res/android"
    android:id="@+id/recyclerModulos"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />

    Código de inicialización dentro de onCreate() después de setContentView():

    val recycler = findViewById<RecyclerView>(R.id.recyclerModulos)
recycler.layoutManager = LinearLayoutManager(this)
recycler.adapter = ModuloRecyclerAdapter(modulos)

    Importa androidx.recyclerview.widget.RecyclerView y androidx.recyclerview.widget.LinearLayoutManager. Aquí modulos debe ser una lista definida previamente, como en el apartado 4.4.

    Para listas cuyos elementos cambian con frecuencia, ListAdapter y DiffUtil permiten calcular y aplicar cambios de forma más precisa que refrescar toda la lista.

    7. Listas con Jetpack Compose¶

    En Jetpack Compose no es necesario utilizar ArrayAdapter, BaseAdapter ni RecyclerView.Adapter. La lista se describe directamente mediante composables.

    import androidx.compose.foundation.layout.Column
import androidx.compose.foundation.lazy.LazyColumn
import androidx.compose.foundation.lazy.items
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable

@Composable
fun ListaModulos(modulos: List<Modulo>) {
    LazyColumn {
        items(modulos, key = { it.nombre }) { modulo ->
            Column {
                Text(text = modulo.nombre)
                Text(text = "Duración: ${modulo.horas} horas")
            }
        }
    }
}

    LazyColumn compone los elementos que necesita mostrar y utiliza claves (key) para mantener la identidad de cada elemento. El nombre se usa aquí como clave únicamente suponiendo que no hay nombres repetidos; en una aplicación real conviene usar un identificador único.

    Comparación¶

    Característica ListView RecyclerView LazyColumn (Compose)
    Tecnología Vistas XML Vistas XML Composables Kotlin
    Adaptador ArrayAdapter / BaseAdapter RecyclerView.Adapter / ListAdapter No necesita adaptador clásico
    Reutilización convertView ViewHolder Composición diferida y reutilización interna
    Actualización Notificación al adaptador Notificación o DiffUtil Recomposición a partir del estado
    Uso recomendado Mantenimiento y aprendizaje Interfaces basadas en vistas Proyectos nuevos con Compose

    9. Fundamentos de las listas declarativas en Compose¶

    En el sistema de vistas tradicional, un Adapter actúa como intermediario entre una colección y las vistas de sus filas. En Jetpack Compose, en cambio, la interfaz es una función del estado: cuando cambia un estado observable leído por un composable, Compose puede recomponer las partes afectadas.

    • Modelo: representa los datos (data class Producto).
    • Estado: almacena los datos que la interfaz debe observar.
    • Composable: describe cómo se dibuja cada elemento.
    • Lista diferida: LazyColumn, LazyRow o las cuadrículas LazyVerticalGrid y LazyHorizontalGrid.
    flowchart TD
    A[Acción del usuario] --> B[Actualizar estado observable]
    B --> C[Recomposición de composables afectados]
    C --> D[LazyColumn muestra los datos actuales]

    Una MutableList normal no es estado observable

    remember { mutableListOf(...) } no garantiza que Compose detecte add() o remove(). Utiliza mutableStateListOf() o un State<List<T>> y reemplaza la lista por una nueva cuando se modifica.

    9.1. Column frente a LazyColumn¶

    Column LazyColumn
    Compone sus hijos declarados directamente Compone los elementos que necesita según la zona visible y su caché
    Adecuada para pocos componentes Adecuada para listas largas o variables
    El desplazamiento requiere, por ejemplo, verticalScroll Integra desplazamiento vertical
    Los elementos se declaran como hijos Se definen mediante item, items o itemsIndexed 
    @Composable
fun ListaSimple() {
    val lenguajes = listOf("Kotlin", "Java", "Python")

    LazyColumn {
        items(lenguajes) { lenguaje ->
            Text(
                text = lenguaje,
                modifier = Modifier.padding(12.dp)
            )
        }
    }
}

    Importaciones principales: androidx.compose.foundation.lazy.LazyColumn, androidx.compose.foundation.lazy.items, androidx.compose.material3.Text, androidx.compose.foundation.layout.padding, androidx.compose.ui.Modifier y androidx.compose.ui.unit.dp.

    9.2. Claves estables e identidad¶

    Cuando se insertan, eliminan o reordenan elementos, las claves estables permiten a Compose asociar correctamente cada elemento con su estado. No debe utilizarse la posición como identidad permanente.

    data class Producto(
    val id: Int,
    val nombre: String,
    val precio: Double
)

@Composable
fun ListaProductos(productos: List<Producto>) {
    LazyColumn {
        items(productos, key = { producto -> producto.id }) { producto ->
            Text("${producto.nombre}: ${producto.precio} €")
        }
    }
}

    El id debe ser único y estable. En una aplicación real puede proceder de una base de datos o generarse al crear el producto.

    10. Ejemplo práctico: lista horizontal de categorías¶

    LazyRow funciona como LazyColumn, pero dispone los elementos horizontalmente. Resulta útil para categorías, filtros o etiquetas.

    @Composable
fun Categorias() {
    val categorias = listOf("Portátiles", "Móviles", "Tablets", "Accesorios")

    LazyRow(
        horizontalArrangement = Arrangement.spacedBy(8.dp),
        contentPadding = PaddingValues(16.dp)
    ) {
        items(categorias) { categoria ->
            ElevatedCard {
                Text(categoria, modifier = Modifier.padding(16.dp))
            }
        }
    }
}

    Importaciones: LazyRow, items, Arrangement, PaddingValues, Modifier, padding, dp, ElevatedCard y Text de los paquetes androidx.compose.foundation.*, androidx.compose.ui.* y androidx.compose.material3.* correspondientes.

    11. Ejemplo completo: gestor de productos con Jetpack Compose¶

    Esta aplicación permite añadir, buscar, marcar y eliminar productos. Utiliza mutableStateListOf() para que la lista sea observable y rememberSaveable para conservar los campos del formulario ante recreaciones habituales de la actividad.

    Crea un proyecto Android Studio con la plantilla Empty Activity y Jetpack Compose con Material 3. Sustituye el contenido de MainActivity.kt por el siguiente código, adaptando el nombre del paquete.

    package com.example.productos

import android.os.Bundle
import androidx.activity.ComponentActivity
import androidx.activity.compose.setContent
import androidx.compose.foundation.layout.*
import androidx.compose.foundation.lazy.LazyColumn
import androidx.compose.foundation.lazy.items
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.runtime.saveable.rememberSaveable
import androidx.compose.ui.Modifier
import androidx.compose.ui.unit.dp

data class ProductoUi(
    val id: Int,
    val nombre: String,
    val precio: Double,
    val comprado: Boolean = false
)

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            MaterialTheme {
                Surface(modifier = Modifier.fillMaxSize()) {
                    GestorProductos()
                }
            }
        }
    }
}

@Composable
fun GestorProductos() {
    var nombre by rememberSaveable { mutableStateOf("") }
    var precio by rememberSaveable { mutableStateOf("") }
    var busqueda by rememberSaveable { mutableStateOf("") }
    var siguienteId by rememberSaveable { mutableIntStateOf(1) }

    val productos = remember { mutableStateListOf<ProductoUi>() }
    val filtrados = productos.filter {
        it.nombre.contains(busqueda, ignoreCase = true)
    }

    Column(
        modifier = Modifier.fillMaxSize().padding(16.dp),
        verticalArrangement = Arrangement.spacedBy(10.dp)
    ) {
        Text("Gestión de productos", style = MaterialTheme.typography.headlineSmall)

        OutlinedTextField(
            value = nombre,
            onValueChange = { nombre = it },
            label = { Text("Nombre") },
            modifier = Modifier.fillMaxWidth(),
            singleLine = true
        )
        OutlinedTextField(
            value = precio,
            onValueChange = { precio = it },
            label = { Text("Precio (ej. 12.50)") },
            modifier = Modifier.fillMaxWidth(),
            singleLine = true
        )

        val precioValido = precio.toDoubleOrNull()?.takeIf { it >= 0 }
        Button(
            onClick = {
                productos.add(ProductoUi(siguienteId++, nombre.trim(), precioValido!!))
                nombre = ""
                precio = ""
            },
            enabled = nombre.isNotBlank() && precioValido != null
        ) {
            Text("Añadir producto")
        }

        OutlinedTextField(
            value = busqueda,
            onValueChange = { busqueda = it },
            label = { Text("Buscar producto") },
            modifier = Modifier.fillMaxWidth(),
            singleLine = true
        )
        Text("Productos: ${productos.size} · Visibles: ${filtrados.size}")

        LazyColumn(
            modifier = Modifier.weight(1f),
            verticalArrangement = Arrangement.spacedBy(8.dp)
        ) {
            items(filtrados, key = { it.id }) { producto ->
                ElevatedCard(modifier = Modifier.fillMaxWidth()) {
                    Row(
                        modifier = Modifier.fillMaxWidth().padding(12.dp),
                        horizontalArrangement = Arrangement.spacedBy(8.dp)
                    ) {
                        Checkbox(
                            checked = producto.comprado,
                            onCheckedChange = { marcado ->
                                val indice = productos.indexOfFirst { it.id == producto.id }
                                if (indice >= 0) {
                                    productos[indice] = producto.copy(comprado = marcado)
                                }
                            }
                        )
                        Column(modifier = Modifier.weight(1f)) {
                            Text(producto.nombre, style = MaterialTheme.typography.titleMedium)
                            Text("${producto.precio} €")
                            if (producto.comprado) Text("Comprado")
                        }
                        TextButton(onClick = { productos.removeAll { it.id == producto.id } }) {
                            Text("Eliminar")
                        }
                    }
                }
            }
        }
    }
}

    Persistencia del estado

    En este ejemplo rememberSaveable conserva los textos y el siguiente identificador en recreaciones compatibles, pero la lista mutableStateListOf() creada con remember no se conserva automáticamente al girar la pantalla ni al finalizar el proceso. Para conservar los productos ante cambios de configuración puede utilizarse un ViewModel; para persistencia duradera, Room. También puede definirse un Saver adecuado para guardar listas pequeñas.

    11.1. Explicación de las operaciones¶

    Código Efecto
    mutableStateListOf<ProductoUi>() Crea una lista mutable observable por Compose.
    productos.add(...) Inserta un elemento y permite actualizar la interfaz.
    productos.filter { ... } Construye una lista filtrada sin modificar la original.
    productos[index] = producto.copy(...) Sustituye el elemento por una copia con un campo modificado.
    items(filtrados, key = { it.id }) Muestra elementos con identidad estable.
    Modifier.weight(1f) Hace que la lista ocupe el espacio vertical disponible en Column.

    11.2. Comprobaciones prácticas¶

    1. Introduce «Teclado» y 25.90; pulsa Añadir producto.
    2. Introduce «Ratón» y 15.50; comprueba que aparecen dos tarjetas.
    3. Escribe «tec» en el buscador: solo debe aparecer «Teclado».
    4. Borra la búsqueda, marca «Ratón» como comprado y comprueba su estado.
    5. Elimina «Teclado» y verifica que disminuye el contador.
    6. Gira el dispositivo y observa qué campos se conservan y cuáles se reinician.

    12. Ejemplo de arquitectura: ViewModel y StateFlow¶

    En aplicaciones más grandes, la interfaz no debería gestionar por sí misma toda la lógica de negocio. Un ViewModel puede exponer un StateFlow que Compose observe mediante collectAsStateWithLifecycle().

    // ProductosViewModel.kt
import androidx.lifecycle.ViewModel
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.update

class ProductosViewModel : ViewModel() {
    private val _productos = MutableStateFlow<List<ProductoUi>>(emptyList())
    val productos = _productos.asStateFlow()

    fun agregar(producto: ProductoUi) {
        _productos.update { lista -> lista + producto }
    }

    fun eliminar(id: Int) {
        _productos.update { lista -> lista.filterNot { it.id == id } }
    }
}

    // Dentro de un composable que recibe el ViewModel
import androidx.compose.runtime.Composable
import androidx.lifecycle.compose.collectAsStateWithLifecycle

@Composable
fun PantallaProductos(viewModel: ProductosViewModel) {
    val productos by viewModel.productos.collectAsStateWithLifecycle()
    ListaProductos(productos.map { Producto(it.id, it.nombre, it.precio) })
}

    El ejemplo reutiliza las clases Producto y ListaProductos del apartado 9.2. Requiere las dependencias compatibles de lifecycle-viewmodel y lifecycle-runtime-compose. El ViewModel sobrevive a cambios de configuración, pero no sustituye a una base de datos ni garantiza conservar datos después de finalizar el proceso.

    13. Errores frecuentes¶

    Problema Causa habitual Solución
    No se actualiza una lista tras add() Se usa remember { mutableListOf() } Usar mutableStateListOf() o reemplazar una lista almacenada en State.
    Se pierde el contenido tras girar Estado almacenado solo con remember rememberSaveable, ViewModel o persistencia según el caso.
    Un elemento conserva el estado de otro al reordenar Falta una clave estable Definir key = { it.id }.
    La lista no aparece dentro de Column Restricciones de altura inadecuadas Dar espacio disponible con Modifier.weight(1f).
    items no se reconoce Falta el import de la extensión Importar androidx.compose.foundation.lazy.items.
