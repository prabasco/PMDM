    Sistema de notificaciones en Android¶

    1. Introducción¶

    Android dispone de distintos mecanismos para comunicar información al usuario. Conviene diferenciar mensajes de la interfaz (Toast y Snackbar), diálogos (AlertDialog) y notificaciones del sistema (que pueden verse fuera de la aplicación). No todos tienen el mismo comportamiento ni necesitan los mismos permisos.

    Mecanismo ¿Dónde aparece? ¿Permite interacción? ¿Funciona fuera de la pantalla de la app? Uso habitual
    Toast Mensaje flotante temporal No No es una notificación persistente del sistema Aviso muy breve
    Snackbar Interfaz de la app Acción opcional No Confirmación y «Deshacer»
    AlertDialog Ventana modal sobre la app Sí No Confirmación de decisiones
    Notificación del sistema Barra de estado, panel y otras superficies según configuración Sí, mediante acciones Sí Recordatorios, mensajes, tareas relevantes

    Regla de diseño

    No utilices una notificación del sistema para confirmar cada pulsación. Usa el componente menos intrusivo que resuelva la necesidad. La presentación final de las notificaciones depende de la versión de Android, el dispositivo, los ajustes y las decisiones del usuario.

    2. Mensajes Toast¶

    Documentación oficial: Toast

    Un Toast presenta un mensaje corto y desaparece automáticamente. Se crea con Toast.makeText(context, texto, duracion).show(). LENGTH_SHORT y LENGTH_LONG indican duraciones aproximadas controladas por el sistema. Desde Android 12, los Toast de texto muestran el icono de la aplicación y el texto está limitado visualmente a dos líneas en las condiciones documentadas por Android. No deben emplearse para mensajes largos ni acciones importantes.

    import android.widget.Toast
import androidx.compose.material3.Button
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.platform.LocalContext

@Composable
fun EjemploToast() {
    val contexto = LocalContext.current

    Button(onClick = {
        Toast.makeText(
            contexto,
            "Tarea completada",
            Toast.LENGTH_SHORT
        ).show()
    }) {
        Text("Completar tarea")
    }
}

    Análisis: LocalContext.current proporciona el contexto Android dentro de Compose. El Toast se lanza al pulsar el botón, no durante la composición. No requiere POST_NOTIFICATIONS.

    3. Snackbar con Material 3¶

    Documentación oficial: Snackbar en Compose

    Una Snackbar informa del resultado de una operación dentro de la aplicación. Puede ofrecer una acción contextual como Deshacer. En Compose Material 3 se utilizan Scaffold, SnackbarHost, SnackbarHostState y una corrutina porque showSnackbar() es una función suspendida.

    3.1. Ejemplo sencillo¶

    import androidx.compose.foundation.layout.padding
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import kotlinx.coroutines.launch

@Composable
fun EjemploSnackbar() {
    val host = remember { SnackbarHostState() }
    val scope = rememberCoroutineScope()

    Scaffold(snackbarHost = { SnackbarHost(hostState = host) }) { padding ->
        Button(
            modifier = Modifier.padding(padding),
            onClick = {
                scope.launch {
                    host.showSnackbar("Datos guardados correctamente")
                }
            }
        ) {
            Text("Guardar datos")
        }
    }
}

    3.2. Ejemplo: eliminar y deshacer¶

    Este ejemplo utiliza rememberSaveable para conservar la lista de cadenas ante recreaciones habituales de la actividad, como un giro de pantalla. La Snackbar ofrece una oportunidad de restaurar la tarea.

    import androidx.compose.foundation.clickable
import androidx.compose.foundation.layout.*
import androidx.compose.foundation.lazy.LazyColumn
import androidx.compose.foundation.lazy.items
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.runtime.saveable.rememberSaveable
import androidx.compose.ui.Modifier
import androidx.compose.ui.unit.dp
import kotlinx.coroutines.launch

@Composable
fun ListaConDeshacer() {
    var tareas by rememberSaveable {
        mutableStateOf(listOf("Estudiar Kotlin", "Practicar Compose", "Entregar práctica"))
    }
    val host = remember { SnackbarHostState() }
    val scope = rememberCoroutineScope()

    Scaffold(snackbarHost = { SnackbarHost(host) }) { padding ->
        LazyColumn(modifier = Modifier.padding(padding)) {
            items(tareas, key = { it }) { tarea ->
                Text(
                    text = tarea,
                    modifier = Modifier
                        .fillMaxWidth()
                        .clickable {
                            val posicion = tareas.indexOf(tarea)
                            tareas = tareas.filterNot { it == tarea }
                            scope.launch {
                                val resultado = host.showSnackbar(
                                    message = "Tarea eliminada: $tarea",
                                    actionLabel = "Deshacer",
                                    withDismissAction = true,
                                    duration = SnackbarDuration.Long
                                )
                                if (resultado == SnackbarResult.ActionPerformed) {
                                    val nuevas = tareas.toMutableList()
                                    nuevas.add(posicion.coerceIn(0, nuevas.size), tarea)
                                    tareas = nuevas
                                }
                            }
                        }
                        .padding(16.dp)
                )
            }
        }
    }
}

    Limitaciones didácticas

    El ejemplo presupone nombres de tareas únicos y operaciones secuenciales. En una aplicación real utiliza identificadores estables, gestiona eliminaciones simultáneas y persiste los datos en una capa de datos (por ejemplo, Room). rememberSaveable no sustituye a una base de datos.

    4. Cuadros de diálogo con AlertDialog¶

    Documentación oficial: diálogos en Compose

    Un diálogo es modal: solicita atención y normalmente una decisión explícita. Resulta apropiado para confirmar acciones destructivas, pero no para comunicar cada éxito rutinario.

    import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.runtime.saveable.rememberSaveable

@Composable
fun EjemploDialogo() {
    var mostrar by rememberSaveable { mutableStateOf(false) }
    var resultado by rememberSaveable { mutableStateOf("Sin cambios") }

    Button(onClick = { mostrar = true }) { Text("Eliminar tarea") }
    Text(resultado)

    if (mostrar) {
        AlertDialog(
            onDismissRequest = { mostrar = false },
            title = { Text("Confirmar eliminación") },
            text = { Text("¿Deseas eliminar esta tarea? Esta acción no se puede deshacer.") },
            confirmButton = {
                TextButton(onClick = {
                    resultado = "Tarea eliminada"
                    mostrar = false
                }) { Text("Eliminar") }
            },
            dismissButton = {
                TextButton(onClick = { mostrar = false }) { Text("Cancelar") }
            }
        )
    }
}

    Conceptos: mostrar controla si el diálogo pertenece al árbol de composición; al cambiar el estado Compose recompone las partes necesarias. onDismissRequest permite cerrarlo por las vías admitidas por el componente. En una lista real, la eliminación se realizaría sobre el estado o repositorio de tareas.

    5. Notificaciones del sistema Android¶

    Descripción general oficial · Crear notificaciones

    Una notificación del sistema es un aviso gestionado por Android que puede permanecer accesible cuando el usuario abandona la app. Puede contener icono pequeño, título, texto, hora, acciones y un PendingIntent para abrir una pantalla. Aunque la interfaz de la app se construya con Compose, las notificaciones del sistema se crean con las API Android y, habitualmente, NotificationCompat.

    5.1. Evolución y compatibilidad¶

    Versión Cambio relevante
    Android 8.0, API 26 Canales de notificación obligatorios para publicar en dispositivos de esta versión o posteriores cuando la app apunta a API 26+
    Android 12, API 31 Exigencia de especificar mutabilidad de PendingIntent para apps con targetSdk 31+; restricciones sobre aperturas indirectas de actividades desde notificaciones
    Android 13, API 33 Permiso de ejecución POST_NOTIFICATIONS para notificaciones no exentas
    Versiones posteriores Evolucionan la presentación y las restricciones de uso; no se garantiza que un aviso aparezca como ventana emergente

    Permiso de notificaciones en Compose · Canales · Cambios Android 12

    5.2. Canales e importancia¶

    En Android 8.0+ las notificaciones deben asociarse a un canal. Cada canal identifica una categoría, por ejemplo, «Recordatorios». El usuario puede modificar sus preferencias. La importancia (IMPORTANCE_LOW, DEFAULT, HIGH, etc.) determina el nivel inicial de interrupción, pero no obliga al sistema a mostrar una ventana emergente. Una vez creado, la aplicación no puede modificar libremente la importancia de ese canal: para otros comportamientos suele necesitar un canal distinto y una estrategia de migración.

    5.3. Permisos¶

    En Android 13+ se declara POST_NOTIFICATIONS en el manifiesto y, para notificaciones no exentas, se solicita en ejecución. Si el usuario lo deniega, no se debe intentar forzar su aceptación. El permiso no es necesario para Toast, Snackbar ni AlertDialog. También es posible que el usuario bloquee todos los avisos de la aplicación o un canal concreto.

    5.4. Ejemplo completo: una notificación desde Jetpack Compose¶

    Objetivo: pulsar un botón, solicitar permiso cuando corresponda, publicar una notificación en el canal «Recordatorios» y abrir MainActivity al tocarla.

    Paso 1. En app/build.gradle.kts, dentro de dependencies, añade AndroidX Core si tu proyecto no lo incluye:

    dependencies {
    implementation("androidx.core:core-ktx:1.17.0")
}

    Versiones de dependencias

    La versión es una referencia de ejemplo, no una afirmación de cuál es la última publicada. Si utilizas catálogo de versiones, declara la dependencia allí y comprueba compatibilidad con el SDK y el resto del proyecto.

    Paso 2. En AndroidManifest.xml, añade el permiso como hijo de <manifest> y fuera de <application>:

    <uses-permission android:name="android.permission.POST_NOTIFICATIONS" />

    Paso 3. Crea un recurso vectorial res/drawable/ic_notificacion.xml desde New > Vector Asset (por ejemplo, un icono de campana). Se utilizará como icono pequeño. Para producción, utiliza un icono monocromático adecuado para la barra de estado.

    Paso 4. Código de MainActivity.kt (ajusta el package):

    package com.example.notificaciones

import android.Manifest
import android.app.NotificationChannel
import android.app.NotificationManager
import android.app.PendingIntent
import android.content.Intent
import android.content.pm.PackageManager
import android.os.Build
import android.os.Bundle
import androidx.activity.ComponentActivity
import androidx.activity.compose.setContent
import androidx.activity.compose.rememberLauncherForActivityResult
import androidx.activity.result.contract.ActivityResultContracts
import androidx.compose.foundation.layout.*
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Modifier
import androidx.compose.ui.platform.LocalContext
import androidx.compose.ui.unit.dp
import androidx.core.app.NotificationCompat
import androidx.core.app.NotificationManagerCompat
import androidx.core.content.ContextCompat

private const val CANAL_ID = "recordatorios"

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        crearCanal()
        setContent { PantallaNotificaciones() }
    }

    private fun crearCanal() {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
            val canal = NotificationChannel(
                CANAL_ID,
                "Recordatorios",
                NotificationManager.IMPORTANCE_DEFAULT
            ).apply {
                description = "Avisos de tareas pendientes"
            }
            getSystemService(NotificationManager::class.java)
                .createNotificationChannel(canal)
        }
    }
}

@Composable
fun PantallaNotificaciones() {
    val contexto = LocalContext.current
    var mensaje by remember { mutableStateOf("Pulsa para crear un aviso") }

    val solicitarPermiso = rememberLauncherForActivityResult(
        ActivityResultContracts.RequestPermission()
    ) { concedido ->
        if (concedido) {
            publicarNotificacion(contexto)
            mensaje = "Notificación enviada"
        } else {
            mensaje = "Permiso de notificaciones denegado"
        }
    }

    Column(Modifier.padding(24.dp), verticalArrangement = Arrangement.spacedBy(16.dp)) {
        Text("Ejemplo de notificaciones", style = MaterialTheme.typography.headlineSmall)
        Text(mensaje)
        Button(onClick = {
            val tienePermiso = Build.VERSION.SDK_INT < Build.VERSION_CODES.TIRAMISU ||
                ContextCompat.checkSelfPermission(
                    contexto, Manifest.permission.POST_NOTIFICATIONS
                ) == PackageManager.PERMISSION_GRANTED

            if (tienePermiso) {
                publicarNotificacion(contexto)
                mensaje = "Solicitud de publicación realizada"
            } else {
                solicitarPermiso.launch(Manifest.permission.POST_NOTIFICATIONS)
            }
        }) {
            Text("Mostrar notificación del sistema")
        }
    }
}

private fun publicarNotificacion(contexto: android.content.Context) {
    val intent = Intent(contexto, MainActivity::class.java)
    val pendingIntent = PendingIntent.getActivity(
        contexto,
        0,
        intent,
        PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
    )

    val notificacion = NotificationCompat.Builder(contexto, CANAL_ID)
        .setSmallIcon(R.drawable.ic_notificacion)
        .setContentTitle("Recordatorio de PMDM")
        .setContentText("Tienes una tarea pendiente de Kotlin")
        .setPriority(NotificationCompat.PRIORITY_DEFAULT)
        .setContentIntent(pendingIntent)
        .setAutoCancel(true)
        .build()

    val permisoConcedido = Build.VERSION.SDK_INT < Build.VERSION_CODES.TIRAMISU ||
        ContextCompat.checkSelfPermission(
            contexto, Manifest.permission.POST_NOTIFICATIONS
        ) == PackageManager.PERMISSION_GRANTED

    if (permisoConcedido && NotificationManagerCompat.from(contexto).areNotificationsEnabled()) {
        try {
            NotificationManagerCompat.from(contexto).notify(1001, notificacion)
        } catch (_: SecurityException) {
            // El permiso puede cambiar entre la comprobación y la publicación.
        }
    }
}

    Comprobaciones importantes

    notify() solicita la publicación, pero no garantiza que el usuario vea un aviso: el canal puede estar desactivado, la importancia puede ser baja o el sistema puede aplicar restricciones. Para una app real, comprueba también el estado del canal y comunica adecuadamente los errores. El ejemplo está pensado para una actividad simple; en producción conviene separar la lógica de notificaciones de la interfaz.

    Flujo de ejecución:

    graph TD
    A[Usuario pulsa botón] --> B{Android 13 o superior y falta permiso?}
    B -->|Sí| C[Solicitar POST_NOTIFICATIONS]
    C --> D{Permiso concedido?}
    D -->|No| E[Mostrar información en la app]
    D -->|Sí| F[Construir notificación]
    B -->|No| F
    F --> G[Comprobar avisos habilitados]
    G --> H[Solicitar publicación al sistema]

    5.5. Acciones, cancelación y actualización¶

    setContentIntent(pendingIntent) define qué sucede al tocar la notificación. setAutoCancel(true) hace que se retire al tocarla, cuando corresponde. El identificador 1001 permite actualizar una notificación publicando otra con el mismo ID o cancelarla:

    NotificationManagerCompat.from(contexto).cancel(1001)

    Para agregar una acción visible se usa addAction(icono, texto, pendingIntent). Una acción que modifica datos debe apuntar a un componente adecuado, con sus correspondientes controles de seguridad. No se debe lanzar indirectamente una Activity desde un BroadcastReceiver como trampolín de notificación en las versiones donde Android lo restringe.

    5.6. Notificaciones locales y notificaciones push¶

    • Local: la propia aplicación crea el aviso en el dispositivo, por ejemplo, al completar un proceso.
    • Push/remota: un servidor envía un mensaje mediante una infraestructura como Firebase Cloud Messaging (FCM). Su recepción y visualización dependen del tipo de mensaje, el estado de la app y los permisos. FCM no es necesario para los ejemplos anteriores.
    • Programada: puede requerir WorkManager para trabajo diferible o mecanismos de alarmas cuando el momento exacto esté justificado. Programar un trabajo no implica que pueda ejecutarse exactamente en un segundo concreto.

    6. Buenas prácticas¶

    1. Elige el componente adecuado: Toast para un mensaje mínimo, Snackbar para feedback con posible acción, AlertDialog para decisiones, notificación del sistema para avisos relevantes fuera de la pantalla actual.
    2. Respeta los permisos: pide POST_NOTIFICATIONS cuando el usuario comprenda su finalidad; admite una negativa.
    3. No abuses de la importancia alta: resérvala para eventos realmente urgentes.
    4. Agrupa y actualiza: evita acumular notificaciones redundantes; usa identificadores y grupos cuando proceda.
    5. Diseña para la accesibilidad: textos claros, acciones comprensibles, sin depender exclusivamente de colores o de mensajes fugaces.
    6. Protege datos sensibles: evita mostrar información privada innecesaria en la pantalla de bloqueo.
    7. Prueba distintos estados: app abierta, segundo plano, permiso denegado, canal silenciado y rotación de pantalla.
    8. Separa responsabilidades: Compose muestra la interfaz; un repositorio o servicio gestiona datos; la capa Android publica notificaciones del sistema.
